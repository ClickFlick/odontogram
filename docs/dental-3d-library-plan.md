# 3D dental chart library — plan

A standalone, npm-published library that renders an interactive 3D mouth in which each
tooth is clickable, plus the Echo integration that shows a tooth's history when it is
clicked. The library is built in **its own repository** by another agent; this document
is the brief for that repo (Part 1) and the plan for wiring it into Echo (Part 2).

Written 2026-09-29. Owner: Omer. **Decided:** open source (MIT), public npm packages under the
`@clickflick` scope, repo `github.com/clickflick/dental-3d`.

---

## What the user should get

In the clinic app, a patient's page gets a **"Teeth" tab**. It shows a 3D mouth. Teeth
that have history are tinted; missing teeth are ghosted. The clinician rotates the
model, clicks a tooth, and a side panel lists everything that happened to that tooth —
every encounter that mentions it, newest first, with the relevant excerpt. Later, the
same panel can show structured status (filling, crown, implant, extracted…).

The library itself knows nothing about patients, encounters or Echo. It renders teeth,
takes a per-tooth state map, and reports selection. Everything clinical stays in Echo.
That is what makes it publishable and reusable.

# Part 1 — The library (separate repo)

## 1.1 Packages

One repo (`clickflick/dental-3d`), two public packages under the `@clickflick` npm org
(create the free org first at npmjs.com — scoped public packages need it). Add
`ngx-dental-viewer`, `dental-chart`, `odontogram`, `three.js` to the `keywords` of both
`package.json`s so Angular developers searching for an `ngx-` package still find it:

| Package                         | What                                                                                                   | Depends on                            |
| ------------------------------- | ------------------------------------------------------------------------------------------------------ | ------------------------------------- |
| `@clickflick/dental-3d`         | Framework-free core: a `DentalViewer` class (three.js), the default 3D model, types, numbering helpers | `three` only                          |
| `@clickflick/dental-3d-angular` | Angular standalone component `<dental-3d>` with signal inputs/outputs wrapping the core                | `@clickflick/dental-3d`, Angular ≥ 21 |

Why a framework-free core: Echo is Angular 21, but the point of an npm package is that
a React/Vue/plain-HTML consumer can use it too. The Angular wrapper is thin (~150 lines).
A `<dental-3d>` web component can be added later from the same core if ever needed.

Tooling: TypeScript 5.9, ESM output, `three` as a **peer dependency** (consumers already
on three.js must not get two copies), Vite for the demo + Vitest for tests, Changesets
for versioning, GitHub Action publishing to npm on tag. Node 22.

## 1.2 The 3D model — generated by the library itself

The mouth is **built procedurally by a script in this repo**, not bought or downloaded.
That settles licensing (the model is our own work, MIT like the code), keeps the file
tiny (< 500 kB), and makes the anatomy parametric. The result is a clean, stylised chart
— recognisable incisors, canines, premolars and molars, not photorealistic enamel. For
"click the tooth to see its history" that is the right look: clearer than a scan, loads
instantly.

`packages/core/model/generate.ts` (Node script, run at build time; output committed as
`default.glb` so consumers never run it):

- **Arch curves.** Upper and lower arch as a parametric curve (catenary/parabola blend)
  using published average adult dimensions: inter-molar width ≈ 55 mm, arch depth
  ≈ 40 mm, upper arch slightly larger than lower so they occlude. Sixteen positions per
  arch, spaced by average mesiodistal tooth widths from dental-anatomy tables (e.g.
  central incisor 8.5 mm, canine 7.5 mm, first molar 10 mm).
- **Tooth shapes.** Four templates — incisor (chisel edge), canine (single cusp),
  premolar (two cusps), molar (four cusps, larger footprint) — each a superellipse
  cross-section lofted from neck to crown with cusps as bumps, then one Loop/Catmull-Clark
  subdivision pass for smoothness. Per-tooth scale from the width table; right side is
  the mirror of the left. Crowns only (no roots) — they are hidden by the gums anyway.
- **Gums.** A tube swept along each arch, blended into the tooth necks, slightly
  translucent pink. Two meshes: `gums_upper`, `gums_lower`.
- **Naming.** Every tooth mesh is named by its FDI code (`11`…`48`); the library only
  ever addresses teeth by name, so a consumer can still supply a different model via
  `modelUrl` (e.g. a commissioned realistic one) as long as it follows the convention.
- **Parameters** (also exposed as generator options for later): arch width/depth,
  crowding, primary dentition (FDI 51–85, smaller teeth, 20 positions) — v2.
- **Output**: glTF 2.0 `.glb`, meshopt-compressed, ≤ 500 kB, model centred at the
  origin, +Y up, upper arch above lower, incisal edge of 11 ≈ 10 mm.

A unit test loads the generated glb and checks: 32 tooth meshes with the right names,
two gum meshes, bounds and orientation, no tooth intersecting its neighbour.

Expect a round or two of iteration with Omer on proportions and look; keep the shape
templates in one file so tweaking is cheap. Photorealism is explicitly not the goal.

## 1.3 Core API (`@clickflick/dental-3d`)

```ts
type Fdi = '11' | '12' | … | '48';                       // permanent; primary codes reserved

type ToothStatus =
  | 'present' | 'missing' | 'implant' | 'crown' | 'filling'
  | 'root-canal' | 'bridge' | 'veneer' | 'extraction-planned' | 'attention';

interface ToothState {
  status?: ToothStatus;          // drives material/visibility (missing = ghosted or hidden)
  tint?: string;                 // any CSS colour; overrides the status colour
  badge?: string | number;       // small label rendered above the tooth (e.g. visit count)
  disabled?: boolean;            // not clickable
  data?: unknown;                // consumer payload, echoed back in events
}

interface DentalViewerOptions {
  container: HTMLElement;
  modelUrl?: string;             // defaults to the bundled model
  numbering?: 'fdi' | 'universal' | 'palmer';   // for labels/tooltips only; API is always FDI
  labels?: boolean;              // tooth numbers rendered as sprites
  theme?: Partial<Theme>;        // colours for tooth, gums, hover, selected, statuses, background
  missingMode?: 'ghost' | 'hide';
  interaction?: { rotate?: boolean; zoom?: boolean; pan?: boolean };
  locale?: 'en' | 'ro' | string; // tooltip strings; consumer can pass its own strings
}

class DentalViewer {
  constructor(opts: DentalViewerOptions);
  ready: Promise<void>;                              // model loaded
  setTeeth(states: Partial<Record<Fdi, ToothState>>): void;   // full replace, diffed internally
  setTooth(fdi: Fdi, state: ToothState | null): void;
  select(fdi: Fdi | null, opts?: { focus?: boolean }): void;  // programmatic selection, optional camera fly-to
  setView(view: 'front' | 'left' | 'right' | 'upper-occlusal' | 'lower-occlusal' | 'reset'): void;
  setJaw(jaw: 'both' | 'upper' | 'lower'): void;
  setOpen(open: boolean): void;                      // mouth open/closed (animated)
  on(event: 'select' | 'hover' | 'ready' | 'error', handler): () => void;
  resize(): void;                                    // also handled by ResizeObserver
  dispose(): void;                                   // frees GPU resources — must be called
}

// events
{ type: 'select', fdi: Fdi | null, state: ToothState | undefined, pointer: { x, y } }
{ type: 'hover',  fdi: Fdi | null }
```

Helpers exported alongside: `toUniversal(fdi)`, `toPalmer(fdi)`, `fromUniversal(n)`,
`isUpper(fdi)`, `quadrant(fdi)`, `ALL_TEETH`.

## 1.4 Behaviour

- **Picking** by raycast on pointer up (not down, so drags don't select). Hover highlights
  the tooth and shows a tooltip with the number in the chosen numbering + status.
  Touch: tap selects, drag rotates, pinch zooms.
- **Camera**: OrbitControls with sane limits (no flipping under the model), damped;
  named views animate over ~400 ms. Double-click a tooth = fly to it.
- **Rendering**: single `requestAnimationFrame` loop that **pauses when nothing changes**
  and when the container is off-screen (`IntersectionObserver`) — a background tab must
  cost nothing. `devicePixelRatio` capped at 2.
- **Materials**: one base tooth material; status/tint applied per mesh by cloning the
  material lazily. Selected = emissive outline (post-processing outline pass is optional;
  a simple emissive + slight scale is enough and cheaper).
- **Keyboard**: the container is focusable; arrow keys move selection along the arch,
  Enter/Space selects, Escape clears, `1`–`5` switch views. Every tooth is also present
  in a visually-hidden list of buttons for screen readers (`aria-pressed` for selected).
- **Theming**: colours come from options, and the Angular wrapper reads CSS custom
  properties (`--dental-tooth`, `--dental-gums`, `--dental-selected`, …) so it follows
  light/dark themes without JS. Background transparent by default.
- **Loading**: three.js and the model are imported dynamically inside `DentalViewer`, so
  a consumer that never opens the tab never downloads them. A `loading`/`error` state is
  exposed; the Angular component renders a skeleton and an error message.
- **Disposal**: geometries, materials, textures, renderer, controls, observers — all
  released in `dispose()`. Test it: creating and disposing 20 viewers must not grow
  `renderer.info.memory`.

## 1.5 Angular wrapper (`@clickflick/dental-3d-angular`)

```html
<dental-3d
  [teeth]="teeth()"
  [selected]="selectedTooth()"
  [numbering]="'fdi'"
  [labels]="true"
  [missingMode]="'ghost'"
  (selectedChange)="onSelect($event)"
  (hoverChange)="…"
  (ready)="…"
/>
```

Standalone component, `ChangeDetectionStrategy.OnPush`, signal inputs (`input()`),
`output()`s, `effect()` pushing input changes into the core, `DestroyRef` → `dispose()`.
No global styles: host is `display:block; position:relative`, consumer sets its size.
Toolbar buttons (views, jaw, open) are **not** part of the component — the demo shows how
to build one from the API, so consumers can style their own.

## 1.7 Acceptance criteria (what "done" means for v1)

1. `npm install @clickflick/dental-3d-angular three` + the snippet in 1.5 renders the mouth in a
   fresh Angular 21 app with no other setup.
2. Clicking any of the 32 teeth emits the right FDI code; hover tooltip is correct in
   all three numbering systems.
3. `setTeeth` with mixed statuses renders visibly different teeth; `missing` ghosts/hides.
4. Works with mouse, touch and keyboard; screen reader can select a tooth.
5. Follows light/dark via CSS variables.
6. Background tab / off-screen: 0 GPU work (verify with Chrome performance panel).
7. Bundle: core ≤ 60 kB gz excluding three.js and the model; model ≤ 500 kB; both lazy.
8. Tests: numbering helpers (unit), model naming (loads the glb), viewer lifecycle
   (jsdom + headless WebGL via `@vitest/browser` or Playwright), dispose leak test.
9. Demo deployed (GitHub Pages) from `main`.
10. `MODEL.md` documents the generator, its parameters and the naming convention; no
    third-party model file is committed.

Suggested milestones: **M1** repo + first generated model (boxes on arches are fine) +
picking + Angular wrapper + demo → **M2** tooth-shape templates that look right, statuses,
theming, a11y → **M3** tests, docs, publish `1.0.0`.

# Part 2 — Echo integration

Nothing here blocks the library work; it is what Echo does once `@clickflick/dental-3d-angular`
exists. Can be built against the M1 model.

## 2.1 What history exists today

Encounters store one markdown `notes` blob. The only tooth-level data is the FDI numbers
the AI writes into that text. `PatientContextService.getToothHistory()`
(`apps/api/src/app/ai/patient-context.service.ts`) already finds encounters whose notes
mention a tooth (regex `(^|[^0-9])<fdi>([^0-9]|$)` on `Encounter.notes`, 10 newest).
That is enough for v1 of the tab: "which teeth were ever mentioned, and where".

## 2.2 API (v1)

- `GET /api/patients/:id/teeth` → `{ [fdi]: { mentions: number, lastDate: string } }`
  — one SQL pass: for each of the 32 codes, count encounters whose notes match, plus the
  latest date. Drives the tint/badge map. `@Require(PATIENTS_READ)`.
- `GET /api/patients/:id/teeth/:fdi` → `ToothHistoryEntry[]` — reuse
  `getToothHistory`, but return the **matching lines** of the note (the section heading
  - the lines containing the number) rather than the first 400 chars, and raise the
    limit to 50. Validates `fdi` against the 32 codes.
- Both audited as READ on `ENCOUNTER` like the other reads (i.e. not recorded — see
  `BaseRepository.audit`).

## 2.3 UI

- `apps/echo-asclepius/src/app/patients/patient-detail/`: new tab **Teeth**
  (`patients.tabs.teeth`, en "Teeth" / ro "Dinți"), lazy-loaded component
  `patient-teeth/patient-teeth.ts` so three.js and the model only load when the tab opens.
- Layout: viewer on the left (min 420 px tall, full width on mobile with the panel
  below), side panel on the right. Toolbar above the viewer: views (front / left / right /
  upper / lower), jaw toggle, open/close, numbering (FDI default, remembered in
  `localStorage`). Built from the library API with Spartan `hlmBtn` buttons.
- Data flow: on open, `GET …/teeth` → `teeth` signal → `[teeth]` input (mentions > 0 →
  `tint` in the primary colour, `badge` = mentions). On `(selectedChange)` →
  `GET …/teeth/:fdi` → panel lists encounters (date, title, excerpt lines with the tooth
  number highlighted via the existing `highlight` pipe), each linking to the encounter
  tab. Empty state: "No visits mention tooth 36 yet." Loading skeleton + error toast per
  the repo conventions (`subscribe({ next, error })`).
- Theme: pass CSS variables from the app's oklch tokens (`--primary`, `--muted`,
  `--card`) into the library's `--dental-*` variables in the component stylesheet.
- i18n keys under `patients.teeth.*` in both `en.json` and `ro.json`.

## 2.4 Later (v2) — structured tooth chart

The 3D chart becomes really useful when each tooth has a **status**, not just mentions:

- Extend the finalize `submit_note` tool (`orchestrator.service.ts`) with an optional
  `teeth: [{ fdi, finding?, procedure?, status? }]` array extracted from the transcript,
  stored in a new per-tenant `ToothEvent` table (`patientId, encounterId, fdi, status,
procedure, note, date`). The clinician reviews it on the review screen like the
  patient summary.
- `GET …/teeth` then returns the latest status per tooth (→ `ToothState.status`), and the
  panel shows a timeline of events instead of text excerpts.
- The migrations rule applies: edit `001_init.sql` in place while there is no prod.

## 2.5 Decisions

- **Names**: repo `clickflick/dental-3d`; packages `@clickflick/dental-3d` and
  `@clickflick/dental-3d-angular`; component selector `<dental-3d>`. Not `ngx-…`: the
  core is framework-free and the name should say so.
- **Licence**: MIT for the code. Public npm packages, free `clickflick` npm org
  (create it on npmjs.com before the first publish).
- **Model**: generated by our own script (Part 1.2). No third-party assets, no licence
  question. A commissioned realistic model can be dropped in later via `modelUrl`.
