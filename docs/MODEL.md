# The 3D model

The mouth shown by `@oozkul/dental-3d` is **generated by this repository**, not bought or
downloaded. `packages/core/model/generate.ts` builds every crown and the gums procedurally and
writes `packages/core/model/default.glb`, which is committed and embedded in the package. Because
the model is our own work it is covered by the same MIT licence as the code, and no third-party
asset is ever committed.

```sh
npm run model:generate          # regenerates default.glb (deterministic)
npx tsx model/generate.ts --check   # in packages/core: also checks neighbour spacing
```

CI fails if `default.glb` is not the output of the current generator.

## Naming convention (the contract)

The library never relies on geometry; it addresses the model **by node name**. A custom model
passed through `modelUrl` works as long as it follows these rules:

| Object               | Name                                  | Notes                                                                                                                                                |
| -------------------- | ------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| Each permanent tooth | FDI code `11` … `48`                  | One node per tooth; the geometry may be on the node itself or on an unnamed / auto-named (`mesh_3`) child, as glTF optimisers like gltfpack produce. |
| Gums                 | anything containing `gum` or `gingiv` | Typically `gums_upper` and `gums_lower`. Anything that is neither a tooth nor gums is treated as gums-like scenery (not pickable).                   |

Name resolution walks **up** from each mesh to the nearest meaningful ancestor name, so
`Scene → 36 → mesh_21` resolves to `36`. `resolveModelName` and `toothCodeOf` are exported if
you want to apply the same rule.

## Coordinate system

- Units are **millimetres**.
- **+Y is up**; the upper arch is above the lower arch.
- The **occlusal plane is y = 0** (crowns of both jaws meet there when the mouth is closed).
- **+Z is labial**: the incisors point towards the viewer; molars sit at negative z.
- The **patient's right is −X** (quadrants 1 and 4), the patient's left is +X (quadrants 2 and 3) — the same convention as a chart drawn facing the patient.
- The model is centred on the origin in x/z. Crown of tooth 11 ≈ 10.5 mm tall.

The viewer re-centres every tooth's geometry on its own bounding box centre at load time, so
node transforms in custom models are fine.

## How the default model is built

All tunable numbers live in **`packages/core/model/shapes.ts`**.

1. **Arch curves.** Each arch is a quarter-ellipse anterior segment (half-width ≈ 28.5 mm upper /
   26.5 mm lower, depth 30 / 26 mm) continued by a nearly straight posterior segment with a
   slight lateral flare, giving an inter-molar width ≈ 55 mm and an arch depth ≈ 45 mm. The upper
   arch is a little larger so it occludes outside the lower one.
2. **Tooth positions.** Sixteen positions per arch spaced by average adult mesiodistal crown
   widths (e.g. upper central incisor 8.5 mm, canine 7.5 mm, first molar 10 mm; lower central
   incisor 5 mm, first molar 11 mm) with a 0.45 mm interproximal gap. The right side is the
   mirror image of the left.
3. **Crown shapes.** Four templates — incisor (chisel edge), canine (single cusp), premolar
   (two cusps), molar (four cusps and a central fossa). Each is a superellipse cross-section
   lofted from the cervical line to the tip: constricted at the neck, widest around a third of
   the height, then "closed" towards the tip independently along the mesiodistal and
   buccolingual axes (a low closing exponent gives a cone/edge, a high one a flat occlusal table).
   Cusps are Gaussian bumps on the occlusal surface. Rings are distributed by profile arc length
   so shoulders and tables are as finely sampled as the sides (40 × 26 grid per crown). Anterior
   crowns are tilted labially by a few degrees. Crowns only — roots are hidden by the gums.
4. **Gums.** A superelliptic tube swept along each arch, following the necks of the teeth
   (so the gingival margin dips around longer teeth like canines) with interdental papillae
   between neighbouring crowns, rounded off behind the third molars. Two meshes,
   `gums_upper` and `gums_lower`.
5. **Export.** A minimal glTF 2.0 binary writer emits one node per mesh; then
   [gltfpack](https://github.com/zeux/meshoptimizer) quantises (`KHR_mesh_quantization`) and
   compresses (`EXT_meshopt_compression`) the file: 38 k vertices, 75 k triangles, **≈ 287 kB**.
   The viewer decodes it with three's bundled `MeshoptDecoder`.

Tests (`packages/core/tests/model.test.ts`) load the committed file and assert: 32 tooth nodes
with the right names, two gum meshes, orientation and bounds, mirror symmetry, and that no crown
intersects its neighbour.

## Planned parameters

The generator is written so these can become options later (v2): arch width/depth, crowding,
and **primary dentition** (FDI 51–85, 20 smaller teeth). Photorealism is explicitly not a goal;
a realistic scan-based model can be supplied through `modelUrl` following the convention above.
