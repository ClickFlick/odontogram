# dental-3d — interactive 3D dental chart

[![CI](https://github.com/ClickFlick/odontogram/actions/workflows/ci.yml/badge.svg)](https://github.com/ClickFlick/odontogram/actions/workflows/ci.yml)
[![npm core](https://img.shields.io/npm/v/@oozkul/dental-3d?label=%40oozkul%2Fdental-3d)](https://www.npmjs.com/package/@oozkul/dental-3d)
[![npm angular](https://img.shields.io/npm/v/@oozkul/dental-3d-angular?label=%40oozkul%2Fdental-3d-angular)](https://www.npmjs.com/package/@oozkul/dental-3d-angular)
[![MIT](https://img.shields.io/badge/license-MIT-blue.svg)](./LICENSE)

An open-source **3D odontogram** for the web: a stylised mouth in which every tooth is
clickable, takes a per-tooth state (status, tint, badge) and reports selection. Built on
three.js, framework-free, with a thin Angular wrapper.

**[Live demo →](https://clickflick.github.io/odontogram/)**

| Package                                           | What                                                                                         |
| ------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| [`@oozkul/dental-3d`](./packages/core)            | Framework-free core: `DentalViewer` class, the procedural 3D model, types, numbering helpers |
| [`@oozkul/dental-3d-angular`](./packages/angular) | Angular ≥ 21 standalone component `<dental-3d>` with signal inputs/outputs                   |

## Highlights

- **32 clickable teeth** addressed by FDI code; hover tooltips and labels in FDI, Universal or Palmer.
- **Per-tooth state**: `present · missing · implant · crown · filling · root-canal · bridge · veneer · extraction-planned · attention`, any CSS tint, a badge, disabled.
- **Named views** (front, left, right, upper/lower occlusal) with animated camera, jaw toggle, mouth open/close, fly-to-tooth.
- **Mouse, touch, keyboard and screen reader**: arrow keys walk the arch, a hidden list of buttons exposes every tooth with `aria-pressed`.
- **Theming through CSS variables** (`--dental-tooth`, `--dental-gums`, `--dental-selected`, …) so it follows your light/dark theme with no JavaScript.
- **Cheap**: renders only when something changes and never while off-screen; three.js and the model load lazily. Core ≈ 12 kB gz, model 287 kB.
- **Own model**: the mouth is generated procedurally by a script in this repo (MIT, no third-party assets). Supply your own glTF via `modelUrl` if you want a realistic one.

## Quick start (plain TypeScript)

```sh
npm install @oozkul/dental-3d three
```

```ts
import { DentalViewer } from '@oozkul/dental-3d';

const viewer = new DentalViewer({ container: document.querySelector('#chart')!, labels: true });
viewer.on('select', (e) => console.log('selected', e.fdi, e.state));
await viewer.ready;
viewer.setTeeth({
  '11': { status: 'crown' },
  '24': { status: 'missing' },
  '36': { status: 'filling', badge: 3, data: { visits: 3 } },
});
```

## Quick start (Angular)

```sh
npm install @oozkul/dental-3d-angular @oozkul/dental-3d three
```

```ts
import { Dental3dComponent } from '@oozkul/dental-3d-angular';

@Component({
  imports: [Dental3dComponent],
  template: `
    <dental-3d
      style="height: 480px"
      [teeth]="teeth()"
      [selected]="selected()"
      [labels]="true"
      (selectedChange)="selected.set($event)"
    />
  `,
})
export class TeethTab {
  teeth = signal<TeethStates>({ '36': { status: 'filling', badge: 3 } });
  selected = signal<Fdi | null>(null);
}
```

See the package READMEs for the full API, and [`docs/MODEL.md`](./docs/MODEL.md) for how the
model is generated and the naming convention custom models must follow.

### Develop

```sh
npm install
npm run dev                 # demo with live reload (http://localhost:5173)
npm test                    # unit + model + headless-browser tests (needs: npx playwright install chromium)
npm run model:generate      # regenerate packages/core/model/default.glb after editing model/shapes.ts
npm run build               # both packages + demo
```

### Release

Releases are tag-driven: `npm run changeset` while you work, then `npm run version`, commit,
`npm run release:tag`, `git push --follow-tags`. The `Release` workflow publishes both
packages to npm with provenance and creates a GitHub Release. Details in
[`docs/RELEASING.md`](./docs/RELEASING.md).
